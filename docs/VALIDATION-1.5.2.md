# Translate Bridge for Zotero 1.5.2 验证记录

## 修复范围与证据

用户报告 1.5.1 中网页和 Zotero 卡顿、网页高亮时隐时现。本次复现并修复网页批注更新路径中的共因，继续使用 Chrome 内置 Google 整页翻译和翻译前不可变英文快照。

旧网页观察器对几乎所有页面文字或节点变化立即清空高亮，等待 700ms 后重新请求 Zotero 批注，再逐条扫描所有候选段落。连续页面更新因此形成“消失—请求—全文定位—重现”；请求失败也会清空已显示批注。服务端每次列出批注还会执行文献检索及附件/批注读取，网页更新会给 Zotero 带来额外工作。

新版将批注数据更新与网页范围更新分开：

- 无关 DOM 更新不清空高亮、不请求 Zotero；正文变化合并为本地重新定位。
- 多条批注共用段落索引；仅让发生变化的段落索引失效。结构或可见性改变时重新确定候选段落，翻译映射仍使用来源身份、完整覆盖和唯一性校验。
- 保留未变化的 CSS Highlight、卡片、编辑框与光标；先计算定位，再更新需要改变的界面。
- 同时发起的读取共用一次请求；编辑/删除成功后要求新的权威读取。删除标记阻止旧请求和后续 DOM 更新恢复已删批注。
- 临时离线保留上次成功读取的批注并提示状态；确认删除或切换文章时仍清除相应数据。
- 初次打开、返回标签页、重新激活浏览器窗口、手动刷新及编辑/删除后更新数据。窗口激活读取有短时节流；网页 DOM 变化本身不读取 Zotero。
- 英文来源捕获合并重复候选和重叠待处理范围，避免同一轮重复遍历。

本轮功能改动位于 Chrome 端。Zotero 1.4.8 引入的原生事件驱动阅读入口保留；没有重新引入阅读器全局轮询。

## 修复前后对照

同一隔离 Chromium 页面构造 100 个正文段落和 20 条批注，运行 `scripts/test-highlight-stability-browser.js`。网络接口使用可控的 Zotero 行为替身，DOM、Range、MutationObserver 与 CSS Highlight 使用真实浏览器实现。通过路由禁用 HTTP 缓存，保证使用当时源码。

| --- | ---: | ---: |
| 首次加载文本遍历次数（含来源捕获） | 2220 | 206 |
| 无关横幅连续更新 8 次：额外批注请求 | 1 | 0 |

## 行为与安全回归

新增 `scripts/test-highlight-lifecycle-browser.js` 覆盖：10 次并发刷新只产生一次请求，编辑内容和光标保留；隐藏/显示正文重新校验范围；删除期间仍在途的旧列表和后续翻译不能恢复已删批注；后台页面变化不请求 Zotero，回到页面能取得 Zotero 端的删除结果。

已有浏览器回归通过：

- 网页批注 9 组：富文本注释安全、精确打开、重复刷新、点击、重复正文拒绝、完整翻译定位、漂移拒绝、删除、离线。
- 综合界面 7 组：编辑保存/冲突草稿、点击、删除、PDF 到网页、导入、无 PDF、队列。
- 文章笔记 9 组及选区异步竞态 4 组。
- 不可变英文快照：101 个物理碎片仍对应原始逻辑句；外来来源拒绝。
- 句子结构矩阵 344 项无失败；200 段/600 句/25 次异步替换性能回归为 737ms，未超过该用例的 5 秒上限。
- 项目自动测试 161 项通过。发布构建还执行扩展清单检查、Zotero TypeScript/XPI 构建；发布后核对 ZIP/XPI 版本、资源和源码一致性。

原始本地日志：`.cache/stability152-before.txt`、`.cache/stability152-after.txt`、`.cache/stability152-lifecycle.txt`、`.cache/stability152-regressions.txt`、`.cache/stability152-tests.log`。打包校验记录与最终哈希见 `progress.md` 对应 1.5.2 检查点。

## 更新与验证边界

1. 当前两端为 1.5.1 时只需更新 Chrome 扩展，无需重新配对或重装 Zotero。
2. 重新加载扩展后，刷新所有已打开的论文标签页；先恢复英文、刷新，再启用 Google 整页翻译。已打开网页中的旧内容脚本不会仅因扩展更新自动停止。
3. 若直接在 Zotero 删除批注，回到文章标签页或手动点击“刷新批注”取得最新状态；持续停留在网页时不因 DOM 变化不断读取文库。暂时离线时看到的是上次成功读取的批注，界面会提示。

本次未操作用户正式 Chrome 配置或 Zotero 文库，未安装插件、提交、推送或发布 GitHub。验证使用隔离 Chromium 和可控接口，没有测量用户运行中的 Chrome/Zotero CPU，也未完成用户实际出版社网页与 Google 实时翻译的长时间使用验收。不能据此声称所有卡顿、所有站点的映射故障均已解决。
