测试日期：2026-09-23。完整包 Chrome 0.8.2 + Zotero 插件 0.6.2。同一包用于 Zotero 9/10。该优化构建随后统一更名为 1.0.0 正式发布，功能实现不变；Chrome 与 Zotero 插件版本均为 1.0.0。更名后的安装包重新构建并通过回归与原生 HTTP 验收。

## 结果

独立运行官方 Windows Zotero 9.0.6 和 10.0.3，固定版本便携运行时，测试库仅安装译桥。未修改正式文库、原 PDF 或用户正在使用的插件。

| 环境 / 集合 | 位置数 | 唯一正确 | 无匹配 | 多处重复 | 错页或越界 |
|---|---:|---:|---:|---:|---:|
| Zotero 9 长段落 | 879 | 843 | 20 | 16 | 0 |
| Zotero 10 长段落 | 879 | 845 | 18 | 16 | 0 |
| Zotero 9 短选段 | 912 | 870 | 16 | 26 | 0 |

| 合计 | 3618 | 3463 | 71 | 84 | 0 |

这里的 3618 是 1809 个选段在两个版本中的检查次数，不是 3618 篇独立论文。观察到的唯一定位率约 95.7%，重复页眉和重复短句保守拒绝，不能将其宣称为全面兼容率。物理论文的 15 个长段落重复来自各页相同的期刊页眉。残余无匹配集中于复杂公式、字符缺失和部分引用文本。

算法更严格后，相比旧版会拒绝部分曾被宽松匹配接受的公式选段。这是为了防止数字、基因编号、不等号或句子中间的不同含义被抹去，并非所有指标都只增不减。

最终未经插桩的交付 XPI 在两版测试库中分别执行 44 次真实 HTTP 请求，共 88 次：24 个选段写入、8 次原批注更新、8 次打开选中位置、1 次配对与版本检查、3 次拒绝用例。退出进程后只读 SQLite 核对：每库 24 个独立批注，原文、译文、笔记、页码、坐标正确；更新未增加重复记录，拒绝用例未新增记录。最终 XPI 与两份实际安装副本 SHA-256 一致。

抽查 6 篇 PDF 的实际保存坐标渲染，检查正文、双栏、裁切页面、表格说明、公式附近的高亮；截图仅保存在本地测试目录。42 项命名回归测试和原有几何匹配套件通过，TypeScript、修改 TS 文件的 ESLint/Prettier、浏览器脚本语法与 ZIP/XPI 完整性检查通过。

## 本轮改进

- 缓存每页文字、分栏顺序、紧凑字符及其物理词坐标索引；使用弱引用，不使已移除文档继续占用强引用缓存。160 页综述的 467 个位置，旧版整批匹配约 116 秒，新版约 3.1 秒；这是本机算法批处理结果，不是每次网页操作的延迟承诺。
- 短句也能使用断词、连字与粘连文字匹配，不再一律要求至少 12 个词。
- 保留数字、基因编号、小数、数值负号与常见数学比较符号，只对明确方括号数值引文做有限归一化；新增相反数值和相反断言的拒绝回归。
- 移除跳过任意中间词和仅凭首尾片段写入高亮的路径。上下文有唯一更强证据时可区分重复句，证据相同时仍拒绝。
- 分栏排序识别分离的左边界，补充三栏交错读取回归；同一识别行内的大间隔拆成独立高亮，避免涂满栏间空白。
- 未创建批注时 API 返回失败状态；浏览器也识别旧版接口的“HTTP 200 但未写入”，防止待同步记录被误计为成功而移除。

## 明确边界

- 扫描图片 PDF 未增加 OCR；加密文件、文字层缺字、纯公式、三页以上连续选区仍可能失败。
- 当前产品以英文原文锚点为中心，未宣称支持所有中文原文论文或任意混合语言。数学符号存在文本层差异时宁可拒绝。
- 正式 Google 整页翻译后的 DOM、所有出版商、网络验证页面、macOS/Linux 未完成穷尽测试；完整浏览器端到端自动验收仍待补足。本轮重点是原文到 PDF 的真实原生链路。
- 适用实际验证版本为 9.0.6/10.0.3，其他小版本仍需回归。安装时两端更新并重启 Zotero、重载 Chrome 扩展、刷新论文页。

## 重现与证据

公开脚本在 `scripts/`，下载正文和测试库仅在 `.cache/corpus-audit/`，不进入发行包或 Git。需要 Python 的 requests、PyMuPDF、beautifulsoup4，以及项目 Node 依赖。

1. `python scripts/prepare-corpus-audit.py` 下载/复用 PDF，记录 SHA-256 并生成独立位置答案。
2. `python scripts/prepare-corpus-selections.py` 生成短选段和官网 HTML 测试。
3. 执行 `node scripts/build-corpus-native.mjs`，生成 `.cache/corpus-audit/native-bundle.js`。运行 `python scripts/setup-native-corpus.py 9` / `10`，仅对独立 profile 中的测试 XPI 加提取脚本；分别以指定 profile 启动相应版本 Zotero，等待 `report.json` 完成。
4. `node scripts/test-corpus-geometry.mjs 10 optimized-10`；附加第四个参数 `short` / `html` 可运行相应集合。对版本 9 重复，输出报告名称须对应 `optimized-9`、`short-9`、`html-9`。
5. `powershell -NoProfile -File scripts/stop-corpus-zotero.ps1` 停止测试实例后，将最终未经插桩的 XPI 装入测试 profile，重新启动；执行 `python scripts/test-corpus-http.py 9` / `10`。
6. 再停止测试实例，执行 `python scripts/verify-corpus-persistence.py`，只读核对落盘并生成可视检查图。

主要本地证据：`manifest.json`、`zotero9/report.json`、`zotero10/report.json`、`optimized-9.json`、`optimized-10.json`、`short-9.json`、`short-10.json`、`html-9.json`、`html-10.json`、`http-final-9.json`、`http-final-10.json`、`persistence.json`。旧版算法性能记录在 `baseline-10.json`；其中初始 CropBox 判据未修正，不使用它的初始越界计数作产品对比。
