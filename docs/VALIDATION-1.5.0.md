# Translate Bridge for Zotero 1.5.0 验证记录

## 修复范围

本版重构 Chrome 端的原文缓存生命周期。英文段落在翻译前建立稳定身份和不可覆盖的句子快照；Google 翻译后的 DOM 只作为中文投影。译文、引用号、空节点和科学符号碎片不能再次登记为英文来源。

稳定段落被整体克隆或替换时，候选段落必须携带该快照的完整来源 marker 集合。相同 marker 可在同一段落中出现多个物理副本，但不再要求全页唯一；只复制部分 marker 到其他段落仍然拒绝。诊断分别报告逻辑 marker 数、物理碎片数和原始英文句子数。

同时补充了句号与数字引用之间存在空格的分句规则，例如 `sentence. 6,7 Next sentence` 中的 `6,7` 仍属于前一句。

## 针对本次现场故障的浏览器验证

`scripts/test-source-snapshot-browser.js` 在 Chromium 中重建以下完整生命周期：

1. 捕获三句英文及稳定段落身份；
2. 用仍为拉丁文字的不完整中间内容改写已捕获段落；
3. 整体替换段落并移除段落身份属性；
4. 把三个逻辑 marker 拆成 101 个物理节点，包含独立引用号、单个中文字和大量空节点；
5. 选择整段中文并恢复最初英文；
6. 把单个 marker 复制到无关段落，确认无法借用原快照。

结果：101 个物理碎片保持为 3 个逻辑 marker 和 3 个原始英文句子；整段恢复原英文，部分外来复制返回 `sentence-cache-missing`。同一测试改用最终 1.4.8 Chrome 包中的 `content.js` 时，整段恢复失败并显示原文标记/覆盖未通过校验。

`scripts/test-source-snapshot-performance-browser.js` 在同一隔离浏览器中一次加入 200 个段落、600 个英文句子，再对一个译文段落执行 25 次异步整体替换。600 个来源身份没有增加，最终仍恢复初始英文；最终源码复测耗时 730ms。该时间只用于发现明显退化，不是不同电脑上的性能承诺。

## 回归验证

- 英文分句45项通过，新增句号后空格加数字引用用例。
- 句子DOM跨领域矩阵344项通过，覆盖普通段落、`div`、内联ID、斜体、链接、上标、换行、克隆、公式及8类论文语料结构。
- 完整原句范围46项通过，覆盖一英多中、从句重排、克隆碎片、跨marker选择、陈旧选区和未知正文拒绝。
- 整段克隆、无ID克隆、旧marker重建、逐句翻译4项通过。
- 克隆引用、空壳marker、句首/句尾漂移、缩写、数值覆盖、引用范围、异步选择及用户报告重建回归通过。
- 诊断显示、侧栏布局、管理区、网页批注、文章笔记及综合界面回归通过。
- 项目自动测试、扩展清单检查、Zotero TypeScript/XPI构建、完整打包与包结构校验均在最终源码上执行。

## 安全边界

- 本版没有让翻译器绕过失效marker、正文缺失、跨段复制、顺序冲突或未知正文；证据不足时继续拒绝同步。
- Chrome Google整页翻译没有公开句子对齐关系。如果它完全删除一个段落的所有来源marker，本版会明确失败，不猜测对应英文。
- Chromium验证使用用户诊断所描述的Google式DOM替换和碎片化重建，并非用户当前Wiley页面的内置翻译现场录制。目标 DOI `10.1002/ctm2.374` 仍需安装后实际复测。
- 本次没有替换正式Chrome/Zotero安装，没有操作正式Zotero文库，也没有提交、推送或发布GitHub。
