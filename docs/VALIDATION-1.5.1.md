# Translate Bridge for Zotero 1.5.1 验证记录

## 修复范围

版本 1.5.0 已正确保存不可变英文快照，并把 45 个物理碎片归并为 8 个逻辑 marker；本版修复其后的数字引用句界判断，以及来源句已保存但物理 marker 全部缺失的问题。

目标诊断来自 DOI `10.1161/circresaha.121.318852`。原文包含 `E14.5.13 The nascent...`、`network.14` 和 `established.13`。旧规则没有把数字结尾的 `E14.5` 后面的 `.13` 识别成“句号加引用”，同时把以 `.13` 结束的完整英文判为非终止，最终产生 `unresolved-sentence-suffix` 与 `english-ending-not-terminal`。

1.5.1 统一使用数字引用终止判断：紧跟句号的单个、逗号列表、范围或方括号引用归入前句；当候选句号位于两个数字之间时，仅在左侧科学数字 token 已含一个小数点时接受后一个点为句界，例如 `E14.5.13`。单独的 `E14.5`、`1.25` 和 `0.05` 仍为非终止小数。单字母附录编号 `B.6` 也被明确排除。

DOI `10.1002/ctm2.374` 的新诊断显示 `sourceSentenceAnchors: 13`，但 `sentenceAnchors` 与 `physicalSentenceFragments` 同时为 0。复现确认 Wiley 式正文会让一个英文句子的起止点跨越多个带 `id` 的行内元素。旧保护为了避免 `Range.extractContents()` 复制这些 `id`，直接跳过整句；当段内所有句子都跨过这种边界时，英文快照存在，但没有任何可随 Google 译文保留的句子 marker。

新版不再放弃这些句子。抽取句子范围后，如果浏览器克隆了带 `id` 的部分祖先，扩展只处理重复标识：原节点仍有实质内容时由原节点保留 `id`；原节点已空时由抽出的节点继承。这样既建立 marker，也不在网页中制造重复 `id`。

## 针对现场文本的验证

- 英文分句专项先在未修复代码上复现：三句被合并成两句，且数字引用句末函数不存在。
- 修复后，`E14.5.13`、`network.14`、`established.13` 分成三个稳定英文句；49 个句界用例全部通过。
- Chromium 重建三句中文与上标引用链接，选区故意不包含最后一个可见引用号；扩展仍恢复三句精确英文，PDF 定位与同步按钮均启用。
- Chromium 另行重建 13 个英文句子，每句跨越两个带 `id` 的 Wiley 式行内节点。修复前稳定复现 13 个来源句、0 个物理 marker；修复后建立 13 个 marker，所有网页 `id` 仍唯一，选择前两句中文可精确恢复前两句英文。
- 保护性反例覆盖普通小数、科学计数、图号、缩写、附录 `B.6`、段落复制和外来 marker 拒绝。

## 回归范围与边界

- 句子 DOM 跨领域矩阵 344 项无失败；其中 Dropout 论文的 `B.6 Alternative Splicing` 保持为原有四句，没有被误拆为五句。新增的带 ID 行内边界、数字引用和 101 物理碎片浏览器用例均通过。
- 完整原句范围、缩写、边界诊断、不可变快照和 101 物理碎片回归无失败。
- 项目自动测试、扩展清单检查、Zotero TypeScript/XPI 构建、完整打包和包结构校验在最终源码上执行。
- Chromium 用例按照用户诊断重建，不是用户当前网页的实时 Google 翻译录制。更新后仍需在目标文章恢复英文、刷新并重新翻译，才能清除 1.5.0 已建立的旧句界。
- 本次没有替换正式 Chrome/Zotero 安装，没有操作 Zotero 文库，也没有提交、推送或发布 GitHub。
